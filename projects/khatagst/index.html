KhataGST

GST filing and input tax credit reconciliation for Indian small businesses.

Business owners photograph their bills. KhataGST turns them into invoices, computes the monthly GSTR-1 and GSTR-3B returns, and answers GST questions with the section of the Act they come from.

01 · Problem

The problem

A registered business in India files GSTR-1 (its sales) by the 11th and GSTR-3B (a summary plus the tax payment) by the 20th, every month. For most small traders the input is paper: supplier bills in a drawer and sales in a notebook. The options are a monthly CA fee, or an evening of retyping bills into Excel where one wrong digit means a return that doesn't reconcile or a credit that shouldn't have been claimed.

The goal I set: get from a photo of a bill to a filing-ready return with as little typing as possible, without ever letting an AI model decide a tax number.

03 · Decisions

Key decisions

1

Money is an integer, always

Every amount is stored and computed in paise, so ₹100.50 is 10050. With floating point, 0.1 + 0.2 is not 0.3, and on a tax return that turns into a rupee that doesn't reconcile.

The subtle case is an intra-state sale, where tax splits equally into CGST and SGST. An odd number of paise can't split evenly, and rounding both halves can create or lose a paisa. Instead, SGST takes the remainder, so the two parts always add back to the total:

2

The model reads, code computes

Gemini only extracts fields from the bill image into a fixed schema: GSTIN, invoice number, date, taxable value, CGST, SGST, IGST and HSN code. Everything after that (the tax split, B2B versus B2C grouping, the GSTR-1 tables and GSTR-3B totals) is plain TypeScript that returns the same output for the same input and can be unit-tested.

Model output is treated as untrusted input. Dates are normalised to ISO format, GSTINs upper-cased, numbers coerced and rounded to paise, and confidence clamped to 0–100. If the JSON comes back malformed, a repair pass strips code fences, fixes smart quotes, quotes bare keys and drops trailing commas before the scan is given up on.

3

Confidence decides how much the user has to check

Every extraction carries a confidence score, and that score decides the next step:

  • > 85Fields are auto-filled
  • 65 – 85Flagged for review
  • < 65Manual entry

If Gemini fails entirely, from quota limits to network errors, the scan is still saved and the user gets an empty review form instead of an error screen. The scanner also asks the API which models the key can use and walks a fallback chain (2.5 Flash, then 2.5 Flash-Lite, then 2.0 Flash), so a retired model name doesn't take the feature down.

4

Answers cite the law, or fall back to it

The AI CA assistant first retrieves the relevant statutory sections: Section 16 (conditions for input tax credit), Section 17(5) (blocked credits), Rules 88A and 86B, Section 50 (interest) and reverse charge. It puts them in the prompt and returns the answer together with the sections it relied on. If the model is unavailable, it returns those sections directly rather than nothing.

For expense checks under Section 17(5), deterministic rules run first and the model refines the result in JSON mode. If the model call fails, the rule-based result stands.

Current state: retrieval is keyword-weighted over a curated set of sections. The pgvector table (768-dimension embeddings with an IVFFlat cosine index) is in place; generating embeddings and switching to semantic search is the next step.

04 · Hardening

Security & reliability

  • Phone OTP login with a 60-second resend cooldown per number and a 5-attempt limit before a new OTP is required. Sessions use JWT.
  • Owner-scoped data. Scan and invoice queries join through the business owner, so guessing another user's ID returns nothing.
  • Payments through Razorpay, with HMAC-SHA256 verification on both checkout signatures and webhooks.
  • API-wide rate limiting, role guards on admin routes, and an upload whitelist (JPG, PNG, WEBP, PDF).
  • Observability: Sentry error tracking, a /health endpoint that probes the database, and Swagger API docs.

05 · Next

What's next

  • Semantic retrieval. Embed the statute sections with Gemini and switch the assistant to pgvector cosine search.
  • GSTR-2B reconciliation. Match purchase invoices against what suppliers actually filed, to catch credit that would otherwise be lost.
  • An evaluation set of real bills to measure extraction accuracy per field, so the 85 / 65 confidence thresholds are tuned on data rather than chosen.
